# TUN 模式

在「工具 → TUN 模式」中选择是否使用 TUN，首页连接按钮负责独立启动或停止代理。关闭 TUN 后仍可连接本地 HTTP/SOCKS 代理；模式会保存在本地。运行中切换模式会自动重连，并保留节点选择和代理链。

TUN 通过鸿蒙 VPN Extension 创建虚拟网卡，把进入 VPN 的应用 TCP、UDP 和 DNS 流量交给 mihomo 内核。首次启动时需允许系统 VPN 授权，不需要为各应用单独配置 HTTP 代理。关闭 TUN 后不创建系统 VPN 或虚拟网卡，改为监听本地混合代理端口，默认地址为 `127.0.0.1:7890`。此时需在支持代理的应用或网络设置中手动填写代理地址。

分应用代理仅在 TUN 开启时生效。白名单决定哪些应用进入 TUN，黑名单决定哪些应用绕过 TUN。进入后的流量仍按规则、全局或直连模式处理，因此 TUN 与全局模式是不同的设置。名单用法见 [分应用代理说明](app-routing.md)。

## 协议栈与 MTU

- 协议栈可选择 `system`、`gvisor` 或 `mixed`，默认 `system`。
- MTU 范围为 1280–9000，默认 1400。系统虚拟网卡与原生内核使用同一个值。
- 设置自动保存在本地。未连接时在下次启动生效；已连接时点击「应用并重连 TUN」，会短暂中断连接，同时保留节点选择、代理链和分应用名单。
- IPv4 与 IPv6 路由均由系统 TUN 接管。IPv6 开关决定内核处理或拒绝进入隧道的 IPv6 流量。

## 实现与验证

设置通过 `vpn-command.json` 随会话传给 VPN Extension。ArkTS 配置系统网卡 MTU，Go 内核读取同一会话中的协议栈和 MTU；`vpn-status.json` 回报当前实际生效的设置。缺少新字段的旧会话沿用 `system / 1400`。

无效协议栈、非整数或越界 MTU 在停止旧连接前被拒绝；原生层也独立校验会话配置。修改协议栈不依赖订阅 YAML 的 `tun` 字段，订阅原文保持不变。

主机测试使用模拟的系统 VPN；Go 测试覆盖会话解析、参数校验、本地 HTTP 代理实际转发，以及连接中更换链式代理出口。真机需验证：首次授权、重复启停、三种协议栈的 TCP/UDP/DNS 连通性、IPv4/IPv6、修改 MTU 后重连，以及分应用名单和代理链的组合行为。
