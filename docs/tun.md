# TUN 模式

在「工具 → TUN 设置」中查看系统 VPN 的连接状态，调整协议栈与 MTU。首页连接按钮负责启动或停止系统 VPN。

鸿蒙系统 VPN 通过虚拟网卡接管流量，因此 LexiClash 在连接时始终创建并使用 TUN，不提供独立关闭 TUN 的开关。首次连接时需允许系统 VPN 授权，连接成功后由系统显示 VPN 图标，无需为各应用手动设置 HTTP 代理。

分应用白名单决定哪些应用进入 VPN，黑名单决定哪些应用绕过 VPN。进入后的流量仍按规则、全局或直连模式处理。名单用法见 [分应用代理说明](app-routing.md)。旧版本中保存的“关闭 TUN”设置会被忽略，升级后连接仍使用系统 VPN。

## 协议栈与 MTU

- 协议栈可选择 `system`、`gvisor` 或 `mixed`，默认 `system`。
- MTU 范围为 1280–9000，默认 1400。系统虚拟网卡与原生内核使用同一个值。
- 设置自动保存在本地。未连接时在下次启动生效；已连接时点击「应用并重连 TUN」，会短暂中断连接，同时保留节点选择、代理链和分应用名单。
- IPv4 与 IPv6 路由均由系统 TUN 接管。IPv6 开关决定内核处理或拒绝进入隧道的 IPv6 流量。

## 实现与验证

后台运行仅使用普通权限 `ohos.permission.KEEP_BACKGROUND_RUNNING` 和 `dataTransfer` 模式，不依赖受限 ACL 权限。连接完成前会确认长时任务申请与首次通知进度更新成功；失败时释放隧道并显示原因。

数据传输通知每分钟更新一次，包含系统要求的 `downloadTemplate`。模板的 `progressValue` 表示完成百分比，持续 VPN 会话保持未完成状态，真实累计流量显示在通知文字中，不将字节数误作百分比。用户关闭后台通知后，不会在返回应用时自动重建任务，需要主动重新连接。系统撤销任务和通知更新失败会记录诊断日志，并在应用中提示。

返回前台和前台运行期间会核对系统中是否存在本应用的 VPN 网卡，避免只凭旧的 `running` 文件或仍可访问的本地控制端口显示“已连接”。诊断记录分别保存在应用沙箱内的 `runtime-ui.log`、`runtime-vpn.log`，包含系统任务取消、进程退出详细原因及资源超限事件，每个文件最多约 64 KiB。

普通长时任务仍受系统业务一致性和资源管控约束，不能保证永不回收。排查后台断开时，重点检查 `LexiClashDiag` 中的任务启动、进度发布、取消原因，以及 UI/VPN 进程退出事件。

设置通过 `vpn-command.json` 随会话传给 VPN Extension。ArkTS 配置系统网卡 MTU，Go 内核读取同一会话中的协议栈和 MTU；`vpn-status.json` 回报当前实际生效的设置。缺少新字段的旧会话沿用 `system / 1400`。

无效协议栈、非整数或越界 MTU 在停止旧连接前被拒绝；原生层也独立校验会话配置。修改协议栈不依赖订阅 YAML 的 `tun` 字段，订阅原文保持不变。

主机测试使用模拟的系统 VPN；Go 测试覆盖会话解析、参数校验，以及连接中更换链式代理出口。真机需验证：首次授权、重复启停、三种协议栈的 TCP/UDP/DNS 连通性、IPv4/IPv6、修改 MTU 后重连，以及分应用名单和代理链的组合行为。

系统 VPN 的虚拟网卡与图标行为见 [华为连接 VPN 指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/net-vpnextension/)。
